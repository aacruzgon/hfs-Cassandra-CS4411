# ADR-aacruzgon-0039: `cassandra_tests` compiles the shared test harness as upstream wrote it, with one fix to `fixtures.rs`

- **Date:** 2026-11-06
- **Status:** accepted
- **Context:**
    - `TestableBackend` lives in `crates/persistence/tests/common/harness.rs`, which names `super::fixtures::TestFixtures` (`:14`) and `super::capabilities::CapabilityMatrix` (`:258`). Implementing it (ADR-aacruzgon-0038) means compiling all three files.
    - No persistence test target declares `mod common;`. The files have never been compiled: `capabilities.rs:6-17` and `tests/backend_error_handling.rs:44` say so, and they have bit-rotted. `fixtures.rs` called `StoredResource::new` with four arguments in five places (`to_stored_resource`), while the function now takes a fifth, `fhir_version` (`src/types/stored_resource.rs:112-118`).
    - Never having been compiled, they were never formatted or linted either. `rustfmt` would rewrite all three (13 hunks in `fixtures.rs`, 20 in `capabilities.rs` as PR #41 left it, 21 before, 3 in `harness.rs`), which CI's required `cargo fmt --check` would then fail on. `capabilities.rs` trips two Clippy lints under CI's `-D warnings` (`derivable_impls` at `:58`, `unwrap_or_default` at `:424` in PR #41's version).
    - `capabilities.rs` belongs to the capability-contract pull request, PR #41 (roadmap section 8: "stale table fixed or removed"). `harness.rs` and `fixtures.rs` are upstream files no Step 2 pull request owns, and neither is on the upstream touch list.
- **Decision:**
    - `tests/cassandra_tests.rs` declares an inline `mod common { pub mod capabilities; pub mod fixtures; pub mod harness; }`, which resolves to `tests/common/*.rs`, each with `#[rustfmt::skip]`. The module allows `dead_code`, `unused_imports`, `clippy::derivable_impls` and `clippy::unwrap_or_default`.
    - The one change to an upstream file: `fixtures.rs`'s five `to_stored_resource` calls pass `FhirVersion::default_enabled()` as the fifth argument, plus the import. Its signature is unchanged; nothing calls it today. `default_enabled()` rather than `FhirVersion::default()`, which is gated on the `R4` feature (`CLAUDE.md`, "FHIR version feature assumption"): `default_enabled()` works in any build, as PR #38's tests use it (`tests/cassandra/create_read.rs:117`).
- **Alternatives considered:**
    - **Format and lint-fix the three files:** lost. It rewrites 36 hunks of upstream code that nothing else compiles, widens the diff against upstream for no behaviour, and edits `capabilities.rs` under PR #41.
    - **Copy `TestableBackend` into a Cassandra file:** lost. The roadmap names `harness.rs` as the interface the suites use (section 5); a copy would drift from it.
    - **Declare `mod common;` through `tests/common/mod.rs`:** lost. It also pulls in `assertions.rs`, which nothing here needs, with the same never-compiled risk.
- **Consequences:**
    - `harness.rs`, `fixtures.rs` and `capabilities.rs` are now compiled, linted (less the allows) and their `#[cfg(test)]` unit tests run, in `cassandra_tests` only. That is the first executed check on them, and it caught the `fixtures.rs` breakage.
    - `capabilities.rs:6-8` ("Cargo never compiles it") and `backend_error_handling.rs:44` are no longer true for the Cassandra binary. The first belongs to PR #41's file; the wording is its to correct. As of PR #49 two places still say the directory is never compiled: `capabilities.rs:8` and `backend_capability_contract.rs:9-11`.
    - **The upstream touch list (roadmap section 8) gains `tests/common/fixtures.rs`** (five arguments and one import). The roadmap edit, in this entry's commit: the section 8 line for `backend_capability_contract.rs` becomes "- `crates/persistence/tests/backend_capability_contract.rs`: Cassandra module; `tests/common/capabilities.rs`: stale table fixed or removed; `tests/common/fixtures.rs`: `FhirVersion::default_enabled()` passed to `StoredResource::new`, so the shared harness compiles; `tests/cassandra_tests.rs`: new binary, which compiles `tests/common/{capabilities,fixtures,harness}.rs` (ADR-aacruzgon-0039)."
    - A later upstream edit to any of the three files can now break `cassandra_tests`, which is in the required `Cassandra schema (single node)` job. That is the point; the fix belongs in the file that broke.
    - `rustfmt::skip` means a later edit to those files is not formatted by `cargo fmt` either; whoever edits them formats by hand, as upstream did.
