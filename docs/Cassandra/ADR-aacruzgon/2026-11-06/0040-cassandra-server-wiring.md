# ADR-aacruzgon-0040: How the server selects and starts the Cassandra backend

- **Date:** 2026-11-06
- **Status:** accepted
- **Context:** Roadmap Step 2's wiring task (item 2.2) adds `StorageBackendMode::Cassandra` to `crates/rest/src/config.rs` and `start_cassandra` to `crates/hfs/src/main.rs`, "modelled on `start_s3` (passing `None` wherever S3 does)". The design (`cassandra-discussion.md`, "What else the server expects from a primary backend") leaves four choices to the implementation: the `HFS_STORAGE_BACKEND` spelling, what `start_cassandra` passes for each optional store and bundle, what a database audit sink does on a Cassandra primary, and how a build without the feature fails. Taking `start_s3` literally does not work: S3 passes `Some` for settings, the bulk-provider store, `$purge`, bulk submit and login sessions, because `S3Backend` implements those traits. The Cassandra backend implements none of them.
- **Decision:**
    - **The value.** `HFS_STORAGE_BACKEND=cassandra`, case-insensitive like the others, with no alias. `Display` gives `cassandra` and `primary_backend_kind` gives `BackendKind::Cassandra`. The invalid-value message lists it.
    - **`start_cassandra` passes `None` for everything the backend does not implement:**
        - login sessions stay in process, with the existing `warn_login_sessions_in_process` warning;
        - no `SettingsStore`, so `/_user/settings` is 501;
        - no `BulkProviderStore`;
        - `OperationsBundle { purge: None, reindex: None, observability: Some(..) }`, so `$purge` and `$reindex` are 501;
        - no bulk export and no bulk submit bundle (501).
    - **What it does pass.** The backend as the UI's tenant-maintenance handle, the `WriteObservability` set shared with the conformance seed, and the SearchParameter refresh task (ADR-aacruzgon-0041).
    - **Startup order.** The SQL-on-FHIR check below, then connect (with `CassandraConfig::from_env_with`, ADR-aacruzgon-0031), then `initialize` (checks that the ten tables exist, never applies `schema.cql`, P6 in ADR-aacruzgon-0027), then the conformance seed, then the stored-SearchParameter load (fail-fast, ADR-aacruzgon-0041), then the refresh task, then serve (`main.rs:4669-4746` at PR #43's head). A connection failure or a missing table stops startup: a missing table and a connect deadline name the schema files; other driver errors go through the generic driver-error mapping.
    - **SQL-on-FHIR.** The backend has no `sof_runner`, and `build_app` panics when `sof_enabled` is on without one (`crates/rest/src/lib.rs:722-732`). `HFS_SOF_ENABLED` defaults to `true` (`config.rs:1516`), so with no change the server panics at startup on every Cassandra boot (seen on the shared node, 2026-11-06). `start_cassandra` turns SOF off with a warning when the operator left `HFS_SOF_ENABLED` unset, so `$viewdefinition-run` and `$sql-run` answer 501 (`handlers/sof/run.rs:466-472`, `handlers/sof/sqlquery.rs:169-175`). When `HFS_SOF_ENABLED` is set explicitly to true, startup fails with a message to unset it. The rule is the panic's own: never silently drop a feature the operator asked for.
    - **Database audit sink.** `HFS_AUDIT_BACKEND=database` on a Cassandra primary fails at startup with an error that names both settings and points at `file` or `cloudwatch`. Before this change it already failed, but through the generic "unsupported for primary backend kind" arm.
    - **Feature off.** Without the `cassandra` feature, `HFS_STORAGE_BACKEND=cassandra` fails at startup with the same `bail!` message the other backends use ("requires the 'cassandra' feature. Build with: …").
    - **The web UI.** The UI's Patient name search is `IdOnly` on Cassandra, as on standalone S3, since Cassandra serves only token, date and URI parameters.
- **Alternatives considered:**
    - **An alias such as `cql`:** lost. Other backends have aliases (`pg`, `mongo`, `objectstore`, `crates/rest/src/config.rs:146-157`) because those names are common shorthand. Nobody writes Cassandra any other way, and each alias is one more spelling to document and test.
    - **Mirroring `start_s3` call for call, with `Some` where S3 has `Some`:** lost. Each `Some` needs a trait the backend does not implement (`SettingsStore`, `BulkProviderStore`, `PurgableStorage`, the bulk-submit job store, `SessionPersistence`). Implementing them is outside the project's scope (the capability matrix and the design's "export and submit bundles (`None`)").
    - **SQL-on-FHIR: require `HFS_SOF_ENABLED=false` on every Cassandra start:** lost. Every operator, script and the Milestone A run would have to remember a setting for a feature the backend never has, and forgetting it is a panic.
    - **SQL-on-FHIR: always turn it off, even when set explicitly:** lost. It drops a feature the operator asked for, which is what `build_app`'s panic exists to prevent.
    - **SQL-on-FHIR through the generic `InProcessSofRunner`, as S3 does:** not now. It needs `ResourceScan` (`crates/persistence/src/sof/in_process.rs:94`; S3 at `backends/s3/storage.rs:1237-1255`), which the backend does not implement, though a scan of the `resources_by_type` partition could serve it. The design neither includes nor excludes SQL-on-FHIR. Revisit if the team wants it.
    - **A SQLite sidecar for bulk-export job state, as MongoDB does:** lost. Bulk export is out of scope, and the export traits are stubs that return 501.
    - **Leave the database audit sink on the generic arm:** lost. It already fails, but its message names neither setting nor what to set instead.
- **Consequences:**
    - Explicit is decided by clap's `value_source("sof_enabled")` (`ServerConfig::sof_enabled_is_explicit`, `config.rs:2038`), so both `HFS_SOF_ENABLED=true` and the bare `--sof-enabled` flag fail startup. Only the built-in default is turned off. The check re-parses the arguments and the environment; if that re-parse fails it answers "not explicit", so an explicit request would be turned off with a warning rather than fail. Startup has already rejected arguments that do not parse, so this should not happen (CodeRabbit raised it on PR #43).

        - **`cassandra-discussion.md`, the `start_cassandra` bullet.** Its last sentence, "Our first version passes `None` wherever S3 does.", becomes: "Our first version passes `None` for every store and bundle the backend does not implement (all of them except `WriteObservability`), because S3's `Some` arms each need a trait the Cassandra backend lacks (ADR-aacruzgon-0040)."
        - **`cassandra-discussion.md`, the "Database audit" bullet** gains: "It fails with an error that names both settings and points at `file` or `cloudwatch` (ADR-aacruzgon-0040)."
        - **`cassandra-discussion.md`, the same section.** It gains a bullet after "Database audit": "**SQL-on-FHIR.** The backend has no `sof_runner`, so `start_cassandra` turns `HFS_SOF_ENABLED` off when it was left at its default, and fails startup when it was set explicitly to true; `$viewdefinition-run` and `$sql-run` answer 501 (ADR-aacruzgon-0040)."
        - **`development-roadmap.md`, Step 2's wiring task.** "(passing `None` wherever S3 does)" becomes "(passing `None` for every store and bundle the backend does not implement, ADR-aacruzgon-0040)".
    - **A follow-up on two stale texts.** `InProcessSofRunner` exists, so the `config.rs:1513-1515` comment and the `build_app` panic text ("use a backend that supports it (sqlite, postgres)", `crates/rest/src/lib.rs:722-732`) are stale. They are upstream text.
    - A Cassandra deployment has no per-user UI settings, its web login sessions do not survive a restart or span nodes, and `$purge`, `$reindex`, bulk export and bulk submit answer 501. Each is a follow-up that needs only a trait implementation and a `Some` here.
    - The book's storage-backends page and the `run-hfs-server` skill document the value, the schema prerequisite and the audit refusal.
    - The `cassandra` feature of `helios-hfs` is now part of the required `cargo clippy (workspace)` job's `--all-features` build, so every `#[cfg(feature = "cassandra")]` arm must stay clippy-clean.
    - Boot time with the conformance seed (about 1,400 creates per tenant) is measured in PR #44 (item 2.6, ADR-aacruzgon-0043).
