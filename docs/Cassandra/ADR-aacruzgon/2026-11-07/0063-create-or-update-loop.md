# ADR-aacruzgon-0063: `create_or_update` is a four-turn loop that checks the id first and each branch's permission after its pre-read, and answers 409 after four definite misses

- **Date:** 2026-11-07
- **Status:** accepted
- **Context:**
    - **What was already decided.** ADR-aacruzgon-0024 made `create_or_update` a bounded loop of compare-and-swaps over create (C1), update (C2) and revive (C4), with 3 retries after definite misses and 2 re-runs after unknown outcomes. D11 put `check_id` first (its 400 against SQLite's 201 is recorded with the other spec tensions in ADR-aacruzgon-0064). D16 made a revive 201. ADR-aacruzgon-0051 requires every later look at the row to be checked against every earlier attempt with an unknown outcome.
    - **What building it raised** (layer L3, PR #59, `crates/persistence/src/backends/cassandra/upsert.rs`):
        - **The permission check.** Walkthrough section 3 (`:324` on `main` `9c8c8f4f3`, before this entry's commit) says every write checks its permission "before any statement runs". `create_or_update` cannot: which operation it is (`Create`, or `Update` for an update or a revive) depends on what R1 finds. SQLite, PostgreSQL and MongoDB check inside `create`, `update` and `restore_deleted` (`sqlite/storage.rs:429`, `:700`, `:1704`), not up front; an up-front `Update` check would refuse a create-only tenant that they allow.
        - **The fourth miss.** Walkthrough 3.5 (`:440` on `main` `9c8c8f4f3`) says a fourth definite miss is `VersionConflict` (409). SQLite, PostgreSQL and MongoDB return the last miss's own error, so a client can get `AlreadyExists` (409) or `NotFound` (404) there.
        - **The overlay on branch a.** The L3 brief said every branch calls `replace_stored_search_parameter`. On branch a that records a removal and drops the tenant's registry for every new SearchParameter the overlay does not hold, which is every spec SearchParameter PUT with a base `url`: the per-resource invalidation #667 removed from seeding.
        - **The late-attempt check across turns.** ADR-aacruzgon-0051's per-turn `check_earlier_attempts` was built into each turn. The L3 worker then found that, in this loop, it can never find an earlier turn's attempt.
- **Decision:**
    - **Each call** is one request (`CasRequest`) of at most 4 turns (`1 + UPSERT_MISS_RETRIES`, `upsert.rs:168`). Before the first turn, `check_id` refuses an invalid id with 400 `invalid` and no statement sent (D11, `:154`).
    - **Each turn** runs, in order: R1; the pre-read check against earlier unknown attempts (ADR-aacruzgon-0051, `:177`); the branch from R1 (a: no row, b: live, c: `deleted_at > 0`); **that branch's permission**, `Create` for a and `Update` for b and c (`:184`); the G38 `code` bound (`:185`); the plan, through `run_cas` for a and c or L2's `update_attempt` for b. A permission or G38 refusal returns at once, as on the other backends, where only `VersionConflict`, `NotFound` and `AlreadyExists` are retried. So walkthrough section 3 gains the exception, and so do the design's `check_permission` row and roadmap Step 3's "at the start of every write".
    - **The answer comes from the plan that applied,** which may be an earlier turn's: a is version 1, `created = true`; b is `created = false`; c is `created = true` (D16). b and c keep the row's `created_at` (G14) and its `fhir_version` (G13).
    - **A fourth definite miss is `VersionConflict` (409)**, against that turn's `N`, whatever the miss was (`:219`). This differs from SQLite, PostgreSQL and MongoDB on purpose: a PUT that lost four races is a conflict, and 404 or "already exists" would misdescribe it.
    - **Branch a notes a new SearchParameter as `create` does** (`note_stored_search_parameter`, `:256`); b and c call `replace_stored_search_parameter` (`:258`). The id has no earlier version, so there is nothing to remove.
    - **The per-turn check stays, although its cross-turn case cannot fire.** This is **[I], inferred from the code**: a turn ends in a definite miss only after a look at or past its target, and that look decides every attempt of the turn (applied, superseded, another writer's, or undecidable, which is an error). An attempt whose condition names a version the row has left can never apply, because versions only grow and `resources` rows are never removed. So the next turn's `check_earlier_attempts`, and `run_cas`'s cross-target `late_attempt(.., Some(target))`, find nothing. **The only evidence** is a mutation: removing the call fails no test (8 mutations of `upsert.rs`; 7 caught). The call is kept: it is free when no outcome was unknown, ADR-aacruzgon-0051 requires it, and it guards the rule if the loop changes.
    - **A `cfg(test)` seam** (`Seam`, `upsert.rs:106`) runs after each turn's R1 and before its CAS, so a test can stage another writer or a fault in a chosen turn. Outside tests it is a zero-size type that does nothing.
- **Alternatives considered:**
    - **Check `Update` up front, before R1:** lost. It refuses a create-only tenant that every other backend allows, and a revive would still need its own check.
    - **Return the fourth miss's own error,** as the other backends do: lost. The walkthrough is the contract for this backend (the Step 3 briefs: "the walkthrough and `write.rs` win"), and a client retrying a PUT should see one status for "lost every race".
    - **`replace` on branch a, as the L3 brief worded it:** lost, for #667's seeding cost above.
    - **Drop the per-turn check, since it cannot fire:** lost. Its cost is nothing on the common path, and removing it would make the loop's correctness rest on an argument no test pins.
- **Consequences:**
    - **Cassandra answers 409 where the other backends may answer 404** after four misses. The race suite asserts that every unconditional PUT succeeds at 4 writers or fewer, so this is reached only above that, and the hot-key benchmark (roadmap section 7's last trigger) watches for it.
    - **A permission refusal can come after one read** (`(read, write, cas) = (1, 0, 0)`), never after a write.
    - **The [I] claim is recorded as unvalidated.** If the loop ever changes so that a turn can end in a miss without deciding its attempts, the check becomes live again; the mutation result should then be re-run.
    - **Tests** (PR #59): `an_invalid_id_is_refused_before_any_statement` (`upsert.rs:671`), `each_branch_checks_its_own_permission` (`:716`), `the_loop_takes_four_turns_then_answers_a_conflict` (`:811`), `a_late_attempt_across_turns_behind_another_writer` (`:1197`), `the_overlay_follows_each_branch` (`:1333`), and the C4 unknown-outcome table.
