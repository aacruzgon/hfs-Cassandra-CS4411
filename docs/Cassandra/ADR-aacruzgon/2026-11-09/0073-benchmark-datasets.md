# ADR-aacruzgon-0073: Benchmark datasets come from our own Synthea run, checksummed as filtered NDJSON

- **Date:** 2026-11-09
- **Status:** accepted (Alan approved it on 2026-11-09, as drafted)
- **Context:** Roadmap row 0.7 needs Synthea datasets of 10,000 and 100,000 resources, Patient and Observation, with version, seed, modules and checksums recorded, and Step 0's exit criterion is regeneration to the recorded checksums. Upstream's corpus (`bulk_1k.tar.gz`) could be filtered to those sizes, but it records no Synthea version or module list, and it sits in a third party's bucket. Step 0 says the generated *bundles* are published as a release asset, and this entry records a different artifact.
- **Decision:** Alan accepted the study's recommendations on 2026-11-09. Measuring them added three inputs, one filter rule and two checks on each run, and Alan decided the five questions that raised later the same day.
    - **Generator:** `synthea-with-dependencies.jar` from release v4.0.0 (SHA-256 `ed43c20ad40ba5c3bc724503a5af032715fe3c491620b766148e7c2361e6ecc1`, refused on mismatch), with `-s 20261108`, `-cs 20261108`, `-r 20260101`, `-p 400` and `--generate.thread_pool_size=4`. The manifest records the release tag, the version in Synthea's metadata (`v3.4.0-18-ga07a65555`), the module list (536 JSON modules, 87 of them top level) and its hash.
    - **Three more inputs are fixed, because leaving them out changes the data:** `-e 20260101` (`-r` does not end the simulation, so it otherwise runs up to the wall clock), `-Duser.timezone=UTC` (Synthea renders dates in the JVM's zone, `birthDate` included), and `exporter.use_uuid_filenames=true` (by default a file name holds the patient's name; in a POSIX locale Java cannot encode a non-ASCII name as a path, so that patient's file is lost and Synthea still exits 0).
    - **Artifact and checksums:** the filtered Patient and Observation resources as sorted NDJSON, cut to exactly 10,000 and 100,000. Sorted by `Patient.id`, each Patient followed by its Observations by `id`. The stream stops at each size, cutting the last patient's Observations, so the 10,000 file is a byte prefix of the 100,000 file. Checksums cover this NDJSON, and it is the release asset, in place of the raw Bundles the roadmap names.
    - **One more filter rule:** Synthea's `disability-adjusted-life-years` and `quality-adjusted-life-years` extensions are removed from Patient, because their last digit differs between x86-64 and arm64.
    - **How both architectures stay covered:** arm64 is the baseline, the Mac plus the Linux arm64 containers. x86-64 is checked by the workflow below. The row 0.6 harness checks each NDJSON file against `SHA256SUMS` before every benchmark run.
    - **The x86-64 check is a CI job, `.github/workflows/benchmark-datasets.yml` (report only, not required):** `generate_datasets.py --verify` on the self-hosted runners, whenever `docs/Cassandra/datasets/**` or the workflow changes, and by hand. It fails on any architecture but x86-64 and installs a pinned Temurin 21.0.13 JRE with `actions/setup-java`. Its report gives the machine, the Java, each file's expected and actual SHA-256, the elapsed time and the memory peak.
    - **Location and language:** `docs/Cassandra/datasets/`, Python standard library only.
    - **Publication:** the release `benchmark-datasets-2026-11-09` holds the two NDJSON files, `manifest.json` and `SHA256SUMS`. Row 0.7 is ticked in this entry's commit, and Alan publishes the release right after the merge, from the commands in the datasets README.
    - **Two checks on each run.** The script compares Synthea's own `Records:` line with the files it wrote, and stops with exit 2 if patients are missing. Plain generation compares its result with the committed `manifest.json` and `SHA256SUMS`, as `--verify` does, says plainly when they differ, and exits 1. The files are still written, since a deliberate change to the recipe needs them.
    - **Alan's five decisions (2026-11-09):** (1) drop the two Patient extensions, after asking how both architectures stay covered and accepting the answer above; (2) the report-only CI job on x86-64, in his words "let's add the alternative report only to a CI job"; (3) `docs/Cassandra/datasets/`, Python standard library; (4) the section 11 edit goes in the same commit as this entry; (5) row 0.7 is ticked in this entry's commit, naming the release tag `benchmark-datasets-2026-11-09`, and Alan publishes the release right after he merges, because that needs no second PR.
    - **Load and create paths:** the load phase uses batch Bundles of PUT entries, 500 entries each by default (`ndjson_to_batches.py`). The create operation measures POST of single resources (Step 0).
- **Alternatives considered:**
    - **Upstream's corpus, filtered:** lost. It cannot record the Synthea version or modules the roadmap requires, and its host can change it.
    - **Synthea's `master-branch-latest`:** lost. It is a moving tag.
    - **Checksums over Synthea's whole output, and publishing the raw Bundles:** lost. Measured by the study: whole Bundles differed between runs, including at the same thread count, in resource types other than Patient and Observation, while the filtered NDJSON hashed identically.
    - **Whole patients only (11,087 and 102,923 resources in the study):** lost. Alan chose exact sizes.
    - **Keeping the quality-of-life extensions and recording one architecture's checksums:** lost. `--verify` would then fail on the x86-64 runners or on the arm64 Macs.
    - **Rounding those two extensions instead of removing them:** lost. It lowers the chance of a last-digit difference without removing it, and no search parameter reads them.
    - **One manual `--verify` on an x86-64 machine instead of a CI job:** the worker's recommendation, not chosen. Alan's words: "let's add the alternative report only to a CI job". A manual run proves one moment, while the job checks again whenever the datasets change.
    - **Ticking row 0.7 in a later commit, once the release exists:** the worker's recommendation, not chosen. Ticking it in this entry's commit, as the orchestrating session recommended, needs no second PR. The cost is that the row's release URL answers 404 between the merge and publication.
    - **The job with no `paths:` filter:** lost. It would spend a minute and under 3 GiB of a runner on every unrelated pull request. The ban on `paths:` covers only the two workflows with required jobs.
    - **A JRE container image instead of `actions/setup-java`:** lost. The script needs Java and Python side by side, so the image would have to carry both.
    - **Setting `LC_ALL=C.UTF-8` for Synthea instead of UUID file names:** lost. That locale is not on every system, and the names would stay in the paths.
    - **Comparing the file count with the population alone:** lost. The population counts only living patients, so the POSIX run's 459 files passed a check against 400; Synthea's own count of 467 did not.
    - **`utils/benchmark-datasets/` or `.github/scripts/`:** lost. Both are upstream directories needing a section 8 line for no gain, and shell with `jq` is awkward for the exact cut, the sort and the decimal text.
    - **Loading the Encounters too:** lost. A third resource type in exactly 10,000 and 100,000 resources would take the place of Observations and change the approved mix.
    - **Stripping `Observation.encounter`:** lost. It alters Synthea's data, and removes a reference that `_include` and reference searches could use later.
- **Consequences:**
    - **Easier:** generation takes about a minute (27 to 65 s of Synthea, up to about 2.5 GB peak RSS), so anyone can regenerate the datasets on demand. Both files load unchanged on PostgreSQL, and the 10,000 file on Cassandra. A change to the recipe that breaks x86-64 shows as a red job on its own pull request.
    - **Harder:** every `Observation.encounter` in the datasets points at an Encounter that is not loaded (99,789 of them in the 100,000 file). Both backends accept them and store them unchanged. A read of that Encounter answers 404, and a search on PostgreSQL still matches by the reference value. A benchmark or demonstration must not expect those Encounters to exist.
    - **Harder:** row 0.7 is ticked before the release exists, so its URL answers 404 between the merge and Alan's publication. The row 0.6 harness now has to do the `SHA256SUMS` check.
    - **Must be revisited:** the checksums are tied to the jar, the seeds, the dates, the time-zone pin, the population and the filter. Any change to them means new checksums. The UUID file names keep the checksums independent of the machine's locale: with that setting off, a run in a POSIX locale loses patients, and the script refuses it. Only 400 people were tested, only Java 17, 21 and 25 were tried (25 only under x86-64 emulation), and both real x86-64 CPUs are AMD, so no Intel CPU has run it. No CI job covers arm64, so a difference that appears only there would show first on a Mac.
