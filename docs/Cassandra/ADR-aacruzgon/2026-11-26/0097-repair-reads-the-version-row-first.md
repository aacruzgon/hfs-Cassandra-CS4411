# ADR-aacruzgon-0097: Repair on read reads the current version's row before it writes, and skips a version with no row (amends ADR-sam-michaels-0006 RV3 and RV4)

- **Date:** 2026-11-26
- **Status:** accepted (Alan confirmed the entry on 2026-11-26)
- **Context:**
    - **The rule as written.**
        - ADR-sam-michaels-0006 RV3 (`0006-step-5-design.md:234`): "Only when a row's tag is below the current version. … Repair never writes `resources`, `resource_versions` or intents."
        - RV4 (`:235`): "No second, serial read before repairing. Trust the tag check's `LOCAL_QUORUM` read of the row."
        - The texts built on them said repair reads nothing more than R1: `cassandra-discussion.md:360` ("so it reads nothing more"), `schema/walkthrough.md` 5.1 step 4 ("so repair reads nothing more") and its table of extra reads ("repair on read | 0"), and `repair.rs`'s Step 6 contract ("so repair needs no other read (RV4)").
    - **The rule it breaks: IW24, in the same ADR.**
        - Decision 2: "Step 4's version row is acknowledged before step 5 is sent, so anything search finds can be opened with vread and `_history`."
        - `write.rs`: "search never finds a version whose row vread and `_history` cannot open".
        - `cassandra-discussion.md:273`: "If the version row failed all its tries, step 5 is skipped and the intent left for the sweeper, which writes both, so anything search finds can be read by version".
        - Since #107 merged (into #106 at `f2d6fd1f2`), the request path skips step 5 when the version row fails. R1 then shows version V, while only V−1's index rows exist. The tag check hides them and queues a repair. Repair could not tell from R1 whether row V exists, so it wrote V's index rows.
    - **How it shows (CodeRabbit on PR #106, thread `PRRT_kwDOVAIJX868UFlR`, D3).** After such a repair, a search finds version V while vread of V answers 404, until the sweeper writes the version row.
    - **Evidence, L1, on a 5.0.9 single node.**
        - On PR #106 at `0b3af4577` (`validate-106-findings`, `report-coderabbit.md` D3): an update whose version row fails all 3 tries (step 2's V3 let through first) answers success (G23), with `resource_versions` holding `[1]` and the type rows tagged `[1]`. After `Repaired { full: true, rows_inserted 5 }` the type rows are tagged **`[2]`**, and vread of version 2 finds **nothing**. The control, a crash after the version row, goes `[1]` → `[2]` with vread of 2 found.
        - On this branch, `repair_skips_a_version_with_no_version_row_and_sends_nothing` with the read removed fails on the type rows: **`[2]` against `[1]`**.
        - **Not shown:** the REST effect (search answers 501 until Step 6); RF 3.
    - **The specs.**
        - **FHIR.** R4 and R4B `search.html` (3.1.1.4.13) and R5 (3.2.1.6.2): "search is only defined to function against the current version of a resource". `http.html`, "Support for Versions" (R4, R4B and R5): "Servers that support this API SHOULD provide full version support", which includes "support vread"; on vread: "Servers are encouraged to support a version specific retrieval of the current version of the resource". Cassandra declares `vread` and `versioning: versioned` (`crates/persistence/README.md`). A search result whose `meta.versionId` vread cannot open is the gap IW24 closes; no SHALL is broken, since vread support is a SHOULD and search answers 501 today, but the rule keeps repair inside what the server declares. Nothing in the three versions conflicts with reading first.
        - **Cassandra.** The read is a single-partition point read of `resource_versions` at `LOCAL_QUORUM`. Writes at `LOCAL_QUORUM` (step 4's version row) and reads at `LOCAL_QUORUM` overlap in at least one replica, so an acknowledged version row is seen; the design already relies on the same overlap for R1 (`cassandra-discussion.md:360`, "a current version seen at quorum is committed").
        - **The design documents.** `cassandra-discussion.md:273` and `:360`; `development-roadmap.md` row 5.3; `schema/walkthrough.md` 5.1 step 4 and the extra-reads table. `crates/persistence/README.md`'s matrix and Discussion #28 (HeliosSoftware/hfs) fix no repair rule; neither conflicts.
    - **ADR-sam-michaels-0008** (on #109's branch `cassandra/step5-crash-tests`, not yet on `main`). Its pull request 6 item 5 already applies IW24 to the sweeper: "When the sweeper's own version-row write fails, it sends no index statement, as the request path does." This entry applies the same rule to repair, the third writer of index rows. Its pull request 7 item 3 says a cut repair's "delta's rows are counted" "if it had started"; with the read, a repair the deadline cuts during its read has started but packed nothing, so it counts no rows, which is what `RepairStats`' doc already says ("counts the rows it packed"). No other 0008 item changes.
    - **Why it is a decision.** It adds a read to repair, against RV4's "nothing else" as the texts above apply it, and a new skip reason: a change to the read path and to the counters. RV3 and RV4 are in Sam's log; Alan co-authored PR #106, so the amendment is recorded here.
- **Decision:**
    - **The read.** After admission (RV5's budget), and before it packs or sends anything, each repair reads R1's version row at `LOCAL_QUORUM`: `SELECT version_id FROM resource_versions WHERE tenant_id = ? AND resource_type = ? AND id = ? AND version_id = ?`.
    - **No row:** nothing is sent. The resource is skipped as `NoVersionRow`, counted (`skipped_no_version_row` in `RepairStats`) and logged as RV9 logs every skip. It is left to the sweeper, which writes the version row and the index rows together.
    - **A failed read:** the repair is `Failed { TriesExhausted }`, with no rows packed, and logged.
    - **Unchanged:** RV3 (repair still never writes `resources`, `resource_versions` or intents) and RV4's ban on a serial read. The only change is this one quorum read.
    - **The new RV4 text:** "No serial read before repairing: trust the tag check's `LOCAL_QUORUM` read of the row. Repair reads only the current version's row of `resource_versions`, at `LOCAL_QUORUM`, and skips the resource if it is missing (IW24; ADR-aacruzgon-0097)."
- **Alternatives considered:**
    - **Accept it as a documented deviation from IW24:** lost. Search would show a version that vread and `_history` cannot open, until the sweeper runs (one grace plus a poll). This is the very case Decision 2 lists against "IW24, steps 4 and 5 at once", and the reason the skip exists.
    - **Repair writes the version row itself, from R1, at `write_ts(V)`:** lost.
        - It would close the gap without a read, and the write is idempotent.
        - But it breaks RV3, and puts a `resource_versions` write in a read request.
        - It also duplicates the sweeper's current-replay case without the intent bookkeeping, so the intent would still replay everything.
    - **Skip a resource that has an intent row:** lost. `pending_index_writes` is clustered by time bucket, so there is no point lookup by resource. And an intent also exists for the ordinary crash after the version row, which repair should heal.
    - **Have the writer mark R1 when the version row is confirmed:** lost. That is a second write to `resources` outside the CAS engine (ADR-aacruzgon-0050), or a schema change.
- **Consequences:**
    - **Built** in `fix(cassandra): repair reads the current version's row first and skips a version with none`, on `fix/cassandra-repair-type-and-version-rows`: `SkipReason::NoVersionRow`, the `skipped_no_version_row` counter, and the read in `send_repair`, so `repair_index` (RV6) reads too.
    - **Tests added:** `repair_skips_a_version_with_no_version_row_and_sends_nothing` (the case and its control) and `a_failed_version_row_read_fails_the_repair_and_sends_nothing`, plus the new counter in `stats.rs`'s test.
    - **Tests changed:**
        - four node tests asserted RV4's "no read" (`(spent.read, spent.serial_read, spent.cas) == (0, 0, 0)`) and now expect one read per admitted repair: `repair_heals_a_crashed_update_at_the_first_search`, `repair_with_an_older_r1_loses_to_a_newer_version`, `repair_retags_a_date_row_the_current_version_still_produces` and `repairs_beyond_the_budget_are_skipped_not_failed`;
        - `skips_behind_cut_repairs_stay_skips_and_the_counters_add_up`: with a zero deadline, the four started repairs are now cut during the read, before they pack, so they report no packed rows (the right report, since they sent nothing). What a repair cut after it packed reports stays covered by the pure test `a_cut_repair_reports_what_it_packed_and_one_that_never_started_nothing`; no node test now cuts a repair mid-batch, since the session has no fault that holds a batch.
    - **Cost:** one `LOCAL_QUORUM` point read per admitted repair: at most 32 per search, 4 in flight, inside the phase deadline, not counted in the 512-row budget. ADR-sam-michaels-0006's measured round trip for one statement is 0.12 ms p50 (`0006-evidence/latency-out.txt`); this read was not benchmarked.
    - **The skip uses budget.** A `NoVersionRow` skip happens after admission, so it has used one of the 32 resources and its rows of the 512. The order of skips in the docs puts it after `Budget`, since only admitted repairs read.
