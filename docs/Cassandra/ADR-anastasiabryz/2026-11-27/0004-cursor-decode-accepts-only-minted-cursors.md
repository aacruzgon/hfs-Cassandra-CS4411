# ADR-anastasiabryz-0004: `paging::decode` accepts only a cursor `mint` could have made: forward, with a `null` bucket slot and the instant written exactly as `mint` writes it

- **Date:** 2026-11-27
- **Status:** accepted
- **Context:**
    - #129 (6d) fills in `C/search/paging.rs`'s `decode` and `mint` (ADR-anastasiabryz-0001). `C/` is `crates/persistence/src/backends/cassandra/`. The design fixes the cursor's shape: a plain `PageCursor` with `sort_values = [<instant, RFC 3339 ms>, <reserved bucket slot>]`, plus `"start"` or `"end"` in a date-only search, and `resource_id = id` (`docs/Cassandra/cassandra-discussion.md`, "The cursor is a plain `PageCursor`"; walkthrough 5.7, 5.10). A malformed cursor, or one of another order or table, is `InvalidCursor`, 400 (`docs/Cassandra/schema/coverage.md` section 5).
    - Three things the design leaves open, which #129 lists or which the code had to settle:
        - **A `Previous` cursor.** `PageCursor` has a `Previous` direction (`crates/persistence/src/types/pagination.rs:155`-`:160`, `PageCursor::previous` at `:175`), and `PageCursor::decode` (`:206`) accepts it. Cassandra pages forward only. #129: "Refusing it, or recording that it's ignored, is Anna's call."
        - **What the reserved bucket slot holds.** Bucketing is not in effect: the design measures partition growth first and buckets only on a trigger, and reserves the slot "so that bucketing can be added without breaking clients" (`cassandra-discussion.md:212`).
        - **How strictly the instant is read.** RFC 3339 has many spellings of one instant (an offset, more or fewer fraction digits).
- **Decision:** `decode` accepts only what `mint` writes, and everything else is `InvalidCursor`:
    - **direction `Next` only.** A `Previous` cursor is refused, not read as `Next`;
    - **the bucket slot is `null`,** always written so by `mint`, and any other value is refused;
    - **the instant must be written exactly as `mint` writes it,** RFC 3339 with three fraction digits and `Z` (`2026-11-26T10:00:00.123Z`), checked by formatting the parsed instant again and comparing;
    - **a non-empty `resource_id`,** exactly two `sort_values` in the default order and three in a date order, a table name of `"start"` or `"end"`, and a table the plan's `Order` reads (ADR-anastasiabryz-0001, `ParamPlan::order`).
    - `mint` writes the instant with milliseconds, a CQL `timestamp`'s precision, so every instant read from the node round-trips exactly. It refuses, as an internal error, a candidate whose order key does not belong to the order it is asked for, which only a bug in the caller can cause.
- **Alternatives considered:**
    - **Read a `Previous` cursor as `Next`.** Lost because the client asked for the page before and would silently get the page after. Cassandra never mints a `Previous` cursor, so one can only come from another backend's link or a hand-made request, and a 400 says so. MongoDB, which does page backwards (`crates/persistence/src/backends/mongodb/search_impl.rs:1603`), is no model here: its sort can be reversed, and Cassandra's clustering order is fixed per table.
    - **Accept any value in the bucket slot and ignore it.** Lost because it would let a cursor that names a bucket be read as if it named none. Once bucketing exists, a cursor's bucket decides which partition to read, so accepting junk now would make it a real value later. Refusing it now keeps every accepted cursor meaningful, and when bucketing comes, `null` can still mean "before bucketing".
    - **Accept any RFC 3339 instant.** Lost because the cursor is opaque and only `mint` makes one. A second spelling of the same instant serves no client and widens what has to be tested. A sub-millisecond instant would also set a bound between two stored values, while no row can be stored there.
- **Consequences:**
    - Easier: a cursor that `decode` accepts is exactly one `mint` produced, so the unit tests list every refused shape (`paging.rs`, `a_malformed_cursor_is_invalid`, `a_cursor_of_another_order_or_table_is_invalid`, `a_previous_cursor_is_invalid`).
    - Harder: a client that edits a cursor gets 400 rather than a best-effort page; that is the intended reading of "opaque".
    - To revisit when bucketing is added: `decode` then accepts a bucket value in the slot, and keeps `null` for the cursors minted before it.
    - The 9 tests copied from `tests/search/pagination_tests.rs` into `tests/cassandra/search_paging.rs` are `#[ignore]`d until `search()` answers (the framework's unfiltered search, #128, row 6.2; `test_pagination_with_filter` also needs #132). Each `#[ignore]` goes in the commit that makes its test pass. That is the testing plan for this step, not a separate decision.
