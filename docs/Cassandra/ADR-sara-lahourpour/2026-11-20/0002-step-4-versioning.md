# ADR-sara-lahourpour-0002: Step 4's three open questions: 409 on a mismatch, live tests for the conditional suite, and `current_version` overridden

- **Date:** 2026-11-20
- **Status:** accepted
- **Context:**
    - Roadmap Step 4 (row 4.1) makes `VersionedStorage` whole on Cassandra. Step 3 left `update_with_match` as the one stub, and its handover ("Open for the Step 4 group") left three questions to Step 4's owner, each with a recommendation; Alan audits the decisions (ADR-aacruzgon-0060). I took Step 4 on 2026-11-20.
    - **The mismatch answer.** Walkthrough 3.3, as signed off (ADR-aacruzgon-0028), gives `update_with_match` a mismatch answer of `OptimisticLockFailure` (412), with a note that Step 4's ADR decides. Upstream's `test_update_with_match_etag_mismatch` (`tests/versioning/optimistic_locking_tests.rs:77-107`) panics unless a stale ETag gives `VersionConflict` (409), and the exit criterion requires `versioning_suite.rs`. SQLite, PostgreSQL, MongoDB and Cassandra's own `delete_with_match` answer 409. No REST handler calls `update_with_match`: REST answers an `If-Match` mismatch with 412 from its own read (`crates/rest/src/error.rs:15-16`).
    - **The conditional suite.** The exit criterion names `search/conditional_if_match_suite.rs`, which drives `conditional_update` and `conditional_delete`, both refused by design on Cassandra (`backends/cassandra/stubs.rs`). Alan ran it on 2026-11-07: both tests fail at the suite's seeding step.
    - **`current_version`.** The trait documents `None` "if the resource doesn't exist or is deleted" (`core/versioned.rs:163`); its default reads through `read`, which answers `Gone` for a deleted resource, on Cassandra as on SQLite. Nothing in production calls it.
    - **The versioning suite** is SQLite-only as written, under fixed tenants; ADR-aacruzgon-0057's adapted copy of the CRUD suite is the precedent for running an upstream suite on the shared node.
- **Decision:**
    - **A mismatch is `VersionConflict` (409),** found on the pre-read with nothing written; a writer landing after the comparison makes `update`'s compare-and-swap miss, which answers 409 for another update and `NotFound` for a delete. `update_with_match` takes `delete_with_match`'s shape and hands the write to `update_resource`, so Step 4 edits no Step 5 file. Walkthrough 3.3 changes from 412 to 409.
    - **Live tests replace `conditional_if_match_suite.rs` in the exit criterion,** beside Step 3's `delete_with_match` tests in `backends/cassandra/versions.rs`: every form of the `If-Match` field updates the version it named; a stale tag, an absent or deleted resource, a tenant without permission and an over-long SearchParameter `code` are refused with nothing written; and another writer, held back by the fault seam until just before the next plain write, lands between the pre-read and the compare-and-swap of both `update_with_match` and `delete_with_match`.
    - **`current_version` is overridden:** an R1 of `version_id` and `deleted_at` only, as `exists` reads only `deleted_at`, answering `None` for an absent or deleted resource, as the trait documents.
    - **`versioning_suite.rs` runs as an adapted copy,** `tests/cassandra/versioning.rs`, on ADR-aacruzgon-0057's terms: the same test names and bodies, the Cassandra node, a fresh tenant for each fixed one, and `test_fhir_version`. Two exclusions, each with its reason in the copy's parity test: `history_tests.rs`, whose 18 tests use the history interactions Cassandra refuses by design; and `test_vread_returns_correct_metadata`, whose last assertion needs versions 1 and 2 to share `created_at`, which `resource_versions` does not store (walkthrough G14).
- **Alternatives considered:**
    - **412 for a mismatch, as walkthrough 3.3 says:** lost. `test_update_with_match_etag_mismatch` would have had to be edited or left out, a deviation from ADR-aacruzgon-0057's "same test names and bodies", and `delete_with_match` would keep 409, since the trait documents `VersionConflict` for it, so the two `_with_match` methods would answer the same `If-Match` differently.
    - **Live tests without the writer-between case:** lost. No test put another writer between a `_with_match` method's pre-read and its compare-and-swap, for either method.
    - **Keep `current_version`'s default:** lost. The documented answer costs one reduced read; Cassandra becomes the one backend that follows the trait doc here, for a method nothing in production calls.
    - **For `test_vread_returns_correct_metadata`, copy it without its last assertion, or keep it with `#[ignore]`:** lost. The first edits a test body; the second needs the parity test to allow an ignored test, which the CRUD copy's forbids. Changing `vread` to read `created_at` from `resources` would change G14, a signed-off decision outside Step 4.
- **Consequences:**
    - Both `_with_match` methods answer a mismatch the same way, and upstream's versioning tests run unchanged on Cassandra: all 21 copied tests pass, and the parity test fails on any upstream change until the copy follows.
    - `update_with_match` costs two reads before its compare-and-swap (its pre-read and `update`'s R1), as `delete_with_match` does; the one-read alternative needs four private items of `update.rs`, a Step 5 file.
    - `update_with_match` leaves the SearchParameter `code` bound (G38) to `update`, which checks it before any statement of its own, so `versions.rs` does not call `write.rs`'s check, which Step 5's extraction pull request removes with every call to it (ADR-aacruzgon-0079; Alan's review of #102). As in SQLite, the pre-read and the comparison now come first: an over-long `code` on an absent or deleted SearchParameter is `NotFound`, and with a stale tag `VersionConflict`, where the roadmap's recommended shape answered 400 for both. Once that pull request removes the refusal, the over-long `code` case of `update_with_match_refuses_without_writing` fails, as `update`'s, `create_or_update`'s and `create`'s do (`update.rs`, `upsert.rs`, `tests/cassandra/create_read.rs`), and goes with them; the note goes to Sam.
    - Cassandra's `current_version` answers `None` for a deleted resource where every other backend answers `Gone`.
    - Row 4.1 is done when `Versioning` is declared, in Step 4's last commit (ADR-aacruzgon-0037).
    - `backends/cassandra/mod.rs`, Step 5's file, still says `update_with_match` answers 501 "until Step 4" and that `current_version` reads through `read`; the change goes to Sam, its owner.
